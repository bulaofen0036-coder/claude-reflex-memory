# claude-reflex-memory · 中文说明

**条件反射，而非检索回忆。** 一套零数据库、零 LLM 调用、纯 markdown 的
Claude Code 记忆架构：教训在**刺激出现的那一刻**自动触发——而不是指望每天
早上把一大份说明书通读一遍。

## 核心思路

多数 agent 记忆项目回答的是「怎么存、怎么搜」（向量库、知识图谱、LLM 抽取
管线）。本项目回答另一个问题：**一条教训应该在什么时候被加载？** 按「触发
方式」给每条教训分层：

| 层 | 装什么 | 何时加载 | 不命中的代价 |
|---|---|---|---|
| `LESSONS.md` | 任何会话都可能撞上的（红线/判断规则/环境坑） | 每会话自动注入 | 常驻，**硬字节预算** |
| `domains/*.md` | 只在某领域深活才用得上的 | 本轮消息或 cwd 命中文件头触发词 | 零——不命中不花一个字节 |
| `reflex_action.py` | 动手那一刻才拦得住的操作红线 | **将要执行的命令原文**命中正则；注入提醒或真拦截 | 零 |
| 你的知识库 | 全部正文，**唯一事实源** | agent 按 `[see: 文件.md]` 深入时才读 | 零 |

三条设计规则：

1. **单写**。正文只写一处（Obsidian 仓库就很合适），上面各层只放以
   `[see: …]` 结尾的一行索引。双写必然分叉，索引不会。
2. **常驻层设硬预算**（默认 19000 字节）。满了不是删教训，是**下沉**到领域
   文件——那里不命中不花钱。（Letta 的 memory block 预算收敛到了同一结论；
   这里由守卫强制执行，不靠自觉。）
3. **守卫查内容，不只查大小**。真正杀死文件型记忆系统的故障，字节计数全都
   抓不住：转义事故写进去的控制字符、文件搬家后的死链、领域文件忘了写触发
   词（内容还在，**但永远不会再被加载**，且没有任何报错）。`reflex_guard.py`
   每次会话开始时全查一遍，并对两个钩子**正反各打一发实弹探测**——死掉的
   钩子返回空，和「本轮不命中」在外部看来一模一样；只测正向的话，「凡问必
   答」的退化实现也能混过去。

## 它不是什么

- 没有数据库、没有 embedding、没有 LLM 调用、没有后台进程。三个纯标准库
  Python 文件。
- 不做自动抓取。教训由你（或按你规矩行事的 agent）提炼；想要自动会话压缩
  请配合 [claude-mem](https://github.com/thedotmack/claude-mem)，两者互补。
- 不是笔记型 MCP server。想让 agent 浏览知识图谱请看
  [basic-memory](https://github.com/basicmachines-co/basic-memory)。
  本项目做的是**让对的教训在对的时刻自己跳出来**。

## 快速上手

```bash
mkdir -p ~/.claude/reflex
cp hooks/*.py            ~/.claude/reflex/
cp templates/LESSONS.md  ~/.claude/reflex/
cp -r templates/domains  ~/.claude/reflex/domains
# 把 templates/settings.hooks.json 合并进 ~/.claude/settings.json（替换 <REFLEX> 路径）
# 可选：export REFLEX_KB=你的知识库路径
python ~/.claude/reflex/reflex_guard.py   # 期望输出 "=== OK reflex self-check ... ==="
```

## 写教训的规矩

一条教训一行：`触发 → 一句正确做法 [see: 文件.md]`。

- 放哪层看**它靠什么触发**（上表），不看主题。
- 新建领域文件**必须**在文件头写 `<!-- triggers: 词1, 词2 -->`，同义词、
  别名、中英文都写全。守卫会大声报没写触发词的文件。
- 结论被推翻时**打失效标记，不删除**：`> ⚠️ 已失效（日期）：被 X 取代`。
  坑的历史本身是资产（Graphiti 双时态思想的一行 markdown 版）。
- 操作红线进 `reflex_action.py`：INJECT（提醒）或 BLOCK（退出码 2 + 理由）。
  每条 BLOCK 必须留明确的钥匙（命令前缀 `PUSH_OK=1`）——没有钥匙的规则是
  堵死的墙，墙迟早被拆。

## 为什么用正则触发而不用检索？

因为提炼后的教训工作集很小（几十 KB），真正致命的不是「搜的时候找不到」，
而是「**你压根没想到要搜的时候它没有跳出来**」。反射由刺激驱动：提示词
关键词、命令行正则、常驻核心，三者合起来做到这一点；向量索引做不到——
你 `git push --force` 的那一刻没有任何东西去查它。

代价也说清楚：这套只适合**提炼后的教训**，不适合原始档案。档案放知识库，
用链接指过去。

## 出处

提取自一位工业自动化工程师（西门子 PLC / TIA Portal 方向）自 2026 年中
以来每天在用的生产系统：约 200MB Obsidian 知识库作唯一事实源、带预算的
LESSONS 层、十来个领域文件、以及每条都「先被违反过至少一次才变成反射」的
操作红线。本仓库的脚本是那套生产配置的去路径化重写版。
